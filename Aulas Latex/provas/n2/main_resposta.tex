    \item A correta alocação da Chave Estrangeira (FK) é fundamental para evitar a redundância de dados e o excesso de valores nulos (NULL). Com base nas definições de mapeamento lógico e físico (SQL), responda o que se pede. Uma biblioteca possui Livros e Editoras. Uma editora pode publicar vários livros, mas cada livro é publicado por apenas uma única editora. Assinale onde a FK deve ser inserida:
    \begin{enumerate}[label=\Alph*)]
        \item A FK deve ser inserida na tabela \textbf{Editora}, pois é a entidade "forte".
        \item \textbf{A FK deve ser inserida na tabela Livro, referenciando a Chave Primária de Editora.}
        \item Deve-se criar uma terceira tabela para armazenar o relacionamento, por ser N:N.
        \item Ambos recebem FK um do outro para garantir a integridade.
        \item Não é necessário o uso de FK neste cenário.
    \end{enumerate}

\noindent
\framebox[\textwidth]{
\begin{minipage}{0.98\textwidth}
\textbf{Resolução (Eliminação do Ternário):}
A melhor forma de resolver um relacionamento ternário (n:n:n) é criando uma entidade associativa, que será denominada \textbf{ESCALA}. Esta nova entidade conterá as chaves estrangeiras que referenciam as três entidades originais e terá uma chave primária composta (ou um ID próprio).
\begin{itemize}
    \item \textbf{ESCALA}(\underline{id\_pat}, \underline{id\_mot}, \underline{placa}, ...)
    \item Onde \texttt{id\_pat} referencia \textbf{Pátio};
    \item Onde \texttt{id\_mot} referencia \textbf{Motorista};
    \item Onde \texttt{placa} referencia \textbf{Caminhão}.
\end{itemize}
Desta forma, os relacionamentos tornam-se binários de 1:N entre as entidades fortes e a entidade associativa.
\end{minipage}
